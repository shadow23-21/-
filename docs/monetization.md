# 变现与收款

## 结论

可以做「用户在你这里付钱，不用自己找 API key」，但**不要卖原始 API key**。正确做法是：

- **BYOK 模式**：用户自带 DeepSeek key，应用免费/一次性解锁。
- **托管模式**：用户买「鲸忆额度」，你的 gateway 用你的 master key 调模型，按次/按 token 扣额度。

用户看到的是「额度/次数」，不是 API key。这样既解决“找不到 API 入口”，又不会把 key 泄露、被转卖、被滥用。

## 为什么不卖 API key

- DeepSeek/智谱的 key 是账号凭证，转卖通常违反服务条款。
- 一个 key 给多人用，无法限流、无法防滥用、无法对账。
- key 泄露后你的账号可能被封、被盗刷。
- 应用商店和支付渠道也会把“卖 key”视为高风险。

## 两种产品模式

| | BYOK | 托管额度 |
|---|---|---|
| 用户操作 | 自己去 DeepSeek 申请 key | 直接在应用内买/兑换 |
| 你的成本 | 0 API 成本 | 你承担 API 成本 |
| 你的收入 | 免费或一次性解锁 | 按次/订阅 |
| 适合 | 技术用户、重度用户 | 普通用户、同人女 |
| 风险 | 无 | 滥用、内容合规、支付合规 |

建议同时保留：默认引导普通用户用「托管额度」，高级设置里保留 BYOK。

## 托管架构

```
App
  → 你的 Gateway（HTTPS）
      → 校验 account token
      → 扣额度 / 限流
      → 用 master key 调 DeepSeek
      → SSE 转发，不存聊天正文
  → 支付/兑换（微信、支付宝、Paddle、兑换码）
      → 加额度
```

数据表最小集：

- `accounts(id, token_hash, credits, created_at, updated_at)`
- `codes(code, credits, used_by, used_at)`
- `orders(id, account_id, amount, channel, status, created_at)`
- `usage(id, account_id, input_tokens, output_tokens, credits, created_at)`

安全要点：

- 用户拿到的是随机 **account token**，不是 API key；token 只存 hash。
- 兑换码一次性使用；绑定账号。
- 每轮限制输入预算（1500 tokens）和输出（400 tokens）。
- 限流、异常检测、退款/封禁。
- Gateway 不记录聊天正文，只记用量。

## 单位经济（按当前 DeepSeek 空闲价）

## 同人女聊天强度（外部数据）

这些是公开资料，不是我们自己的用户数据；上线后以 `usage` 表为准。

- **Replika**：官方数据称用户平均每天约 **70 条消息**，少数超过 2 小时 → 约 2,100 条/月。([网易转载](https://m.163.com/dy/article/KC15FDHD05198R91.html))
- **星野/Talkie**：广发证券研报引用灼识咨询，用户日均使用 **70 分钟以上**，MAU 2,005 万、付费用户 139 万。([报告摘要](https://www.sgpjbg.com/labelsyh/minimaxtalkiexingyeaipeiban.html))
- **Character.AI**：平均单次会话约 **17.4 分钟**，有评测称重度用户日均约 2 小时；付费转化约 2%。([统计页](https://axis-intelligence.com/wp-content/dashboard/character-ai-statistics-dashboard.html)、[评测](https://www.aixq.cc/29026.html))
- **语C 人工委托**：Plurk 上可见 150–300/周、500–3,000/月的报价（币种/地区不同，仅作意愿参考）。([搜索页](https://www.plurk.com/search?q=%e5%b0%88%e5%b1%ac%e8%a7%92%e5%b8%b3))
- **DeepSeek 限额事件**：有报道同人女把 DeepSeek 当乙游玩，聊天记录几十万字，限额后大量差评；说明重度用户真实存在。([搜狐](https://biznews.sohu.com/a/1103781095_99969083))

换算：

- 正常 70 条/天 ≈ 2,100 条/月 → 3,000 次包够用。
- 中度 100 条/天 ≈ 3,000 条/月 → 刚好。
- 重度 200 条/天 ≈ 6,000 条/月 → 8,000 次包。
- 按 ¥0.002/轮，3,000 次成本约 ¥6；¥19.9 仍有约 70% 毛利。

结论：**¥19.9 = 3,000 次**是合理的主力档；不要做“无限量”，重度用户用 8,000 次包或加购。

## 收款渠道

### 直接发 APK（Android）

| 渠道 | 需要 | 适合 |
|---|---|---|
| 微信支付/支付宝 | 个体户或公司营业执照、商户号 | 长期正规收款 |
| 爱发电 / 微店 / 闲鱼 | 个人可开始；卖兑换码 | **最快验证付费** |
| Paddle / Lemon Squeezy | 海外主体或支持的国家；MoR 代缴税 | 海外用户 |
| Stripe | 海外/香港/新加坡主体；大陆个人难 | 海外网站 |

个人阶段最现实：**爱发电/微店卖兑换码**，用户买到码后在 App 里兑换额度。你不用先接支付 API。

### Google Play

- 数字内容/额度必须走 **Google Play Billing**（15%–30%）。
- 不能引导用户去外部支付（有例外，但 AI 额度不适用）。
- 新个人账号通常还要 12 人 × 14 天封闭测试。

### Apple App Store

- 数字额度必须走 **Apple IAP**（30%，小企业 15%）。
- AI 陪伴/角色扮演通常 17+，需要举报/屏蔽/UGC 审核。
- 中国大陆区还要 AIGC 备案 + 安全评估。

### 国内安卓商店

- 需要公司主体、软著、ICP、安全评估、算法/AIGC 备案、未成年人保护。
- 支付走微信/支付宝商户号，开发票。
- 个人开发者基本走不通。

## 平台与合规

- **不得卖 raw API key**；卖的是应用内服务额度。
- AI 生成内容要标识；要有举报/屏蔽/年龄门。
- 《人工智能拟人化互动服务管理暂行办法》要求安全评估、算法备案、未成年人保护、防沉迷。
- 收款要能退款、开发票、处理投诉；支付渠道会查业务合规。
- 同人角色涉及第三方 IP：只做用户自导入，不做官方角色市场。

## 分阶段落地

### 阶段 1：兑换码（0–1 个月）

- Gateway 加 accounts/credits/codes。
- `scripts/make-codes.mjs` 生成一次性兑换码。
- App 加「鲸忆额度」：输入兑换码、显示剩余次数、托管聊天。
- 在爱发电/微店卖码；先卖 20 个体验包验证。

### 阶段 2：接支付（1–3 个月）

- 有量后注册个体户/公司，开微信/支付宝商户号。
- Gateway 加 `/api/pay/create` + 回调加额度。
- 或海外用 Paddle/Lemon Squeezy。

### 阶段 3：商店 IAP（3–6 个月）

- Google Play Billing / Apple IAP。
- 补内容审核、举报、年龄门、隐私政策、商店素材。

## 下一步开发清单

1. Gateway：SQLite `billing.db`、`/api/redeem`、`/api/balance`、托管 `/api/chat` 扣额度。
2. 脚本：`make-codes.mjs` 生成/导出兑换码。
3. App：设置页「鲸忆额度」面板、兑换码输入、余额显示、托管模式。
4. 管理：简单 CLI 查订单/用量/封禁。
5. 部署：公网 HTTPS gateway（Cloudflare Worker + D1，或轻量 VPS）。

## 建议

先做 **兑换码 + 托管额度**，不要一上来接微信/支付宝。原因：

- 不需要商户号就能开始收钱（爱发电/微店）。
- 能验证“普通用户愿不愿意为免 key 付费”。
- 等有 50 个付费用户，再接正式支付和商店 IAP。

如果验证下来没人愿意付，说明产品价值还不够，继续做免费 BYOK + 口碑，比先接支付更划算。
